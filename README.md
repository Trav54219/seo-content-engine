# seo-content-engine

A small, offline SEO and content-marketing toolkit in plain Python (standard library only; pytest for tests).

> **All data in this repo is synthetic.** The keyword list, search volumes, difficulty scores, HTML pages and "Search Console" rows are generated by `generate_data.py` with a fixed seed for a made-up home-coffee site ("Bean Atlas", `example.invalid`). **Nothing is connected to Ahrefs, Semrush, Google Search Console or any other service**, and no network calls are made. The outputs demonstrate the method, not real-world results or rankings.

## What it does

| Module | Job |
|---|---|
| `keywords.py` | Classify keywords by search intent (informational / commercial / transactional / navigational), discover topic themes, build intent clusters, plan one pillar per theme |
| `briefs.py` | Rule-based content brief per cluster: primary/secondary keywords, outline by intent, target length, meta title/description within length limits, schema suggestion, internal links |
| `audit.py` | Static on-page audit of local HTML: title, meta description, H1/heading order, word count, canonical, lang, Open Graph, JSON-LD validity, internal links, anchor text, alt text |
| `audit.py` (CWV-style) | Static proxies only: images without width/height (layout-shift risk), render-blocking head scripts, missing lazy-loading, viewport. These are **not** measured Core Web Vitals |
| `links.py` | Internal-link recommender: unlinked mentions of another page's target phrase, orphan detection, pages with no inbound links prioritised |
| `calendar.py` | Editorial calendar CSV: pillars first, then supporting pages by opportunity, on fixed publish weekdays |
| `performance.py` | Report over Search Console-shaped CSV: period-over-period clicks, CTR, weighted position; flags decaying pages, striking-distance (positions 8-20), and low CTR for position |

## Run

```bash
python -m pytest -q                 # tests
python generate_data.py             # regenerate synthetic data (deterministic)
python -m seo_engine run-all        # writes ./out (clusters, briefs/, calendar, audit, links, performance)
```

`out/` is committed so you can read example output without running anything.

## Design notes and limits

- **Opportunity score** = volume / (difficulty + 10). A relative ranking aid, not a traffic forecast.
- **Intent** is keyword-rule based. It is transparent and testable but will misclassify edge cases; real SERP-based intent would be better.
- **Theme discovery** is greedy most-common-token grouping with intent words excluded. It works on tidy lists like the sample; messy real lists would need embeddings or SERP overlap.
- **Link recommender** matches exact target phrases, so it finds only literal mentions.
- **CTR expectations** in the performance report come from an assumed curve (`EXPECTED_CTR`), not measured data. Replace it with your own.
- Synthetic page flaws (missing meta, bad JSON-LD, double H1, etc.) are planted on purpose so the audit has something to find.
- To use real data, supply files with the same columns: `keywords.csv` (`keyword,volume,difficulty`), `gsc.csv` (`date,page,query,clicks,impressions,position`), `pages.csv` (`path,target_keyword`) and a folder of `.html` files, then `python -m seo_engine run-all --data <dir>`.
